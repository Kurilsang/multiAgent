# ADR-0004：任务生命周期不绑定 HTTP 连接

日期：2026-10-10 · 状态：已采纳 · 关联：[ADR-0001](0001-state-machine-for-react-loop.md)、[ADR-0002](0002-dual-layer-termination.md)、[ADR-0003](0003-multi-agent-orchestration.md)、[SPEC-0004](../specs/0004-multi-agent.md)、[SPEC-0005](../specs/0005-session-persistence.md)

## 背景：被修正的旧决策

SPEC-0004 明确记录「客户端断连（生成器 `GeneratorExit`）为兜底同样置取消」——即**断连即叫停**。该决策假设断连时收尾分支一定会执行。

实测证伪（SPEC-0005 grilling 会话，真实 `app.server` + 真实引擎 + 慢速 fake，客户端在流中途断开）：

- Starlette 用 `iterate_in_threadpool` → `anyio.to_thread.run_sync` 驱动**同步生成器**，默认 `abandon_on_cancel=False`（shielded CancelScope），生成器被直接遗弃，**收尾分支从不执行**；
- 后果链：会话锁（当时在生成器体内持有）**永久不释放** → `GET /export` 超时；`_current_cancel` 永久残留；审计日志停在断连那一刻；
- `POST /agent/stop` 返回 `{"status":"ok","stopped":true}` 却**毫无作用**——取消标志只在迭代边界轮询，而引擎正卡在厂商调用里。

也就是说，文档承诺的「断连即取消叫停」实际是「断连即遗弃 + 锁泄漏 + 服务逐渐僵死」。**一次误刷新就能让服务不可用**。

## 决策

任务的**生命周期与标识独立于 HTTP 连接**，连接只是订阅者：

1. **任务在后台执行体运行**（每任务一个守护线程），产出的事件带单调 `seq` 与时间戳写入内存缓冲，并同时追加审计 JSONL。
2. **SSE 端点退化为订阅者**：只从缓冲读取并转发，不持有任务、不持有会话锁。**断连 = 退订**——不置取消标志、不清理任何东西，任务照常跑完。
3. **停止按标识定位**（`POST /agent/stop` 带 `task_id`，缺省停该会话的在跑任务），且取消必须能在**厂商流内部**被观察到——只在迭代边界轮询会让「停止」在长调用期间形同虚设。
4. **锁拓扑拆分为「每会话锁 + 管理面独立锁」**：会话锁只保证同一会话的历史写入不交错；技能 / MCP 管理写操作改用管理锁，**不再被在跑任务阻塞**（旧拓扑下装个技能要等任务跑完）。
5. **同会话并发一律明确拒绝**（409，不排队）：任务在跑或聊天轮次进行中，再发起任务/聊天都被明确告知，而不是静默阻塞或交错写入。
6. **重连续流**：客户端凭 `task_id` + 已收最大 `seq` 重连，服务端先补发缺口再转实时；同一任务的事件广播给所有订阅者。订阅者积压超限时补一帧 `truncated` 告知从哪个序号重连，**不静默截断**。
7. **进程重启后不续跑**（承接 SPEC-0005 的非目标）：内存缓冲消失后，从审计日志补出历史事件并**明确标注「已中断」**，不假装任务还活着。审计日志是任务事件的唯一权威副本，SQLite 只存任务索引（归属、状态、起止、日志路径）。

## 被否决的替代

- **保留断连即取消，只修收尾分支**：修不了——收尾分支不可达是 Starlette 驱动同步生成器的方式决定的，不是漏写 `finally`。要么改异步生成器（全面 asyncio 化，代价远超收益），要么把任务移出请求生命周期（本决策）。
- **任务留在请求内、用 `BackgroundTasks`**：仍绑定请求生命周期，且拿不到逐事件订阅与重连语义。
- **断连后让任务继续但不可重连**：任务跑完的结果无人可见，等于后台烧 token；重连是「继续跑」这个决策成立的前提。
- **进程重启后续跑同一任务**：进程死亡时正在执行的工具调用可能已产生副作用（写文件、外部请求、MCP 调用），续跑要么至少一次重放（可能重复副作用）、要么跳过（可能丢结果），两者都需要工具级幂等性契约——当前不存在。且 MCP 会话、在飞厂商流、线程池 future、旁存句柄池都不可恢复。**重启后可回看、可重跑，不续跑**。
- **多进程部署 + 数据库协调**：会把「网关逻辑（路由/鉴权）」提前拖进来；单进程边界明确（检测到共享数据目录即拒绝启动）更符合当前定位。

## 后果

- **正面**：一次断连不再污染整个服务；长任务不再阻塞管理面；多会话可并行推进；刷新页面能接回在跑的任务并回看全部历史。
- **代价**：任务有了独立生命周期，就必须自己管理「谁在跑、跑到哪、谁来收尾」——这带来了任务索引、事件缓冲上限、订阅者溢出处理与停机收尾窗口（置取消后最多等 5 秒）。
- **诚实边界**：守护线程随进程退出，硬杀时正在跑的任务其答案会丢（审计日志留下半截轨迹，UI 标注「已中断」）；这是「不续跑」决策的直接体现，不是缺陷。
