# ADR-0005：上下文装配采用预算分层，条数截断退居保底

日期：2026-10-12 · 状态：已采纳 · 关联：[ADR-0002](0002-dual-layer-termination.md)、[ADR-0003](0003-multi-agent-orchestration.md)、[SPEC-0005](../specs/0005-session-persistence.md)、[SPEC-0006](../specs/0006-context-memory.md)、CONTEXT.md「上下文预算」「记忆块」「滚动摘要」「观察值视图」

## 背景：被修正的旧决策

入模上下文一直只有一条规则——**按条数取最近 N 条**（`MAX_CONTEXT_MESSAGES`，保留 system 之外一律「旧的不要」）。这条规则假设「条数」能近似「体积」。

实测证伪（SPEC-0006 grilling 会话，读代码 + 对账）：

- 截断决策**不知道自己在省什么**：20 条短消息可能只有 3k token，20 条带大观察值的消息可能超过 100k token，系统对此毫无感知；一条工具观察值视图就占 4000 字符。
- 全仓 `token_count` / `context_window` **零命中**——没有任何 token 计数或窗口概念。
- 同时，**全量历史一直完整保存在会话库里**（SPEC-0005），页面展示全量、可导出，唯独发给模型的那部分用最粗暴的方式裁剪。**失忆不是数据丢了，是该喂进去的没喂进去**。

也就是说，「长对话失忆」不是记忆系统的缺失，而是**装配入模时缺乏判断力**。旧决策把「按条数截断」当记忆问题的解法，实为记错了解法。

## 决策

**入模从「取最近 N 条」换成「按预算分层装配」**，条数截断退居「最近保底」：

1. **token 估算为零依赖纯函数**（无 tokenizer）：CJK/全角按 1 token/字，非 CJK 按 1 token/3 字符，每条消息加固定结构开销，向上取整。目的不是精确，是一致且保守——**宁可少装不可爆窗**。
2. **上下文预算** = `CONTEXT_WINDOW_TOKENS` − `CONTEXT_OUTPUT_RESERVE_TOKENS`。预算是硬约束，装配器在预算内按优先级从高到低装填。
3. **分层装填**：system → 记忆块（摘要）→ 最近 N 条**保底**（`MAX_CONTEXT_MESSAGES` 语义由「截断上限」变为「保底下限」）→ 更早对话（预算有剩余才逐字入模）。观察值视图随剩余预算收缩到保底下限，全文旁存续读。
4. **超预算动作阶梯**：① 装不下的更早对话**吸收进滚动摘要**（每会话一条、覆盖水位单调、合并旧摘要），摘要作为记忆块注入；② 仍超则观察值视图等比压缩至保底；③ 连保底都装不下时硬截断到 system + 最新一条，标 `degraded`。
5. **摘要即记忆接口**：装配器只认识「记忆块」这一抽象（一段文本，注入位固定）。本决策只落地「会话内滚动摘要」一种来源；**跨会话长期记忆作为第二种来源留接口**，接入时不动装配、截断与摘要逻辑。
6. **摘要生成走现有对话通道**（装配期同步惰性触发、落库后不重复），失败降级硬截断、对话不阻塞。摘要永远只是入模视图，**原话全量留会话库**，可回查、可导出。

## 被否决的替代

- **维持按条数截断，只调大 N**：治标——N 调大仍是「不知道体积」，大观察值一来照样爆窗，短对话又浪费。
- **先上 tokenizer 做精确计数**：引入第三方依赖与厂商差异，而收益是「更精确的保守估算」——估算偏保守本来就该留余量，精确化的边际收益不成比例。留作后续（`max_tokens` 计费对账需要时再引入）。
- **先做向量检索/长期记忆**：那是另一棵树（记忆归属维度、写入者、召回策略），且当前失忆痛点是「该喂的没喂进去」，不是「检索不到」。先把会话内装配做对，跨会话记忆留接口。
- **摘要即数据清理（删旧消息）**：混淆「入模视图」与「数据资产」。摘要只影响发给模型的窗口，历史本体永不删除——坏摘要的兜底是原话可回查，而非追求摘要完美。

## 后果

- **正面**：长对话不再因条数硬切而自相矛盾；早期约束经摘要在上下文里存活；大工具结果不再挤爆窗口；每次入模有账（`context_meta` 报出估算占用/预算/压缩水位/是否降级）。
- **代价**：装配逻辑变复杂（分层 + 降级阶梯 + 滚动摘要 + 记忆块抽象），多一次摘要 LLM 调用（仅超预算触发），需要一张摘要表（会话库迁移 v3）。
- **诚实边界**：token 是零依赖估算、偏保守，会「用不完预算」；摘要质量依赖当前模型的指令遵循，坏摘要只能靠「原话在库里可回查」兜底，而非摘要本身可靠。`MAX_CONTEXT_MESSAGES` 的语义从上限变保底，需要在配置注释与 README 写明，避免旧配置被误读。
