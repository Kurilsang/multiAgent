# SPEC-0003：MCP 市场与 MCP 工具接入

状态：已定稿（grilling 会话逐条确认 + to-spec 测试缝确认）· 日期：2026-09-24
关联：[ADR-0001](../adr/0001-state-machine-for-react-loop.md)、[ADR-0002](../adr/0002-dual-layer-termination.md)、[SPEC-0001](0001-skill-market.md)、[SPEC-0002](0002-skill-catalog.md)、CONTEXT.md「工具」「技能」「技能市场」「在线目录」「目录包」

## 问题（Problem Statement）

MCP 生态已有大量现成的工具服务器（GitHub、文件系统、数据库、各类 SaaS），但本服务无法接入：用户要么手写代码自行对接 MCP 协议，要么眼看着技能市场里装的只是提示词技能、调不动真实外部能力。高级用户想接入自建的内网 MCP 服务也没有一等公民的配置入口。需要一个与技能市场同构的「MCP 市场」：在线浏览、单次确认、安装即用，同时本地配置优先、手写即生效。

## 方案（Solution）

以技能市场的心智做 MCP 市场：在统一的市场视图里浏览/搜索官方 MCP Registry 的 server 条目 → 点「安装」弹出单次确认卡，完整展示能力声明（stdio 拼装后的命令原文、远程 endpoint 与域名、宿主要求、必填密钥表单）→ 确认后安装为一份人类可读可改的**连接定义** → 启用即把该服务暴露的**工具**灌入工具注册表，聊天与任务两条通道立刻可被模型调用。

本地配置优先：一切安装产物都是可手改的声明式连接定义文件（密钥只以 `${VAR}` 占位引用 `.env`），手写同格式文件接入自建 MCP 服务与市场安装完全同权；文件态是唯一事实源，改动经重载生效。

## 用户故事（User Stories）

1. 作为内部用户，我想在统一的市场视图里浏览和搜索官方 MCP Registry 的 server 条目（名称/描述/版本/热度/徽标），以便像逛技能市场一样发现可接入的工具能力。
2. 作为内部用户，我想在安装前看到单次确认卡展示完整能力声明——stdio 服务拼装后的完整命令原文、远程服务的 endpoint URL 与域名、宿主运行器要求（npx/uvx/docker/dnx）、repository 源码链接——以便清楚知道「安装并启用」等于授权了什么。
3. 作为内部用户，我想在确认卡上按 Registry 的结构化声明（环境变量/请求头，含 isSecret/isRequired/default/choices）填写必填配置与密钥（密钥走密码框），以便一次确认就完成密钥配置、不用手翻 `.env`。
4. 作为内部用户，我想让安装产物是人类可读的连接定义且密钥只以 `${VAR}` 占位，以便放心导出、分享、进版本库。
5. 作为内部用户，我想直接手写连接定义文件接入自建 MCP 服务（内网 stdio 进程或自建 streamable-http 端点），以便不经市场也能接入私有能力，且体验与市场安装一致。
6. 作为内部用户，我想改完连接定义文件后执行重载（或重启）即生效，以便延续技能包「文件态是唯一事实源」的编辑习惯。
7. 作为内部用户，我想对已安装的 MCP 服务执行查看/启用/禁用/删除，以便管理体验与技能市场完全一致。
8. 作为内部用户，我想让禁用某个 MCP 服务后其全部工具立即从可调用集合消失，以便确切控制模型的能力边界。
9. 作为内部用户，我想在聊天对话中让模型直接调用已启用 MCP 服务的工具（无需任何激活步骤），以便「装了即用」。
10. 作为内部用户，我想让任务通道（Agent 循环）同样可用 MCP 工具，以便复杂任务能利用外部工具能力。
11. 作为内部用户，我想让工具结果被截断成视图时在尾注看到全文大小与续读方法，以便模型知道还能取回完整结果。
12. 作为 Agent（模型），我想通过 `read_tool_result(handle, offset)` 分段取回被截断的完整观察值，以便需要全文时能完整获取、而不需要时不开销上下文。
13. 作为内部用户，我想按 MCP 服务配置观察值视图大小（含 0 = 全量直灌不截断），以便对大结果工具（文件读取、搜索）自主权衡完整性与上下文成本。
14. 作为内部用户，我想让某个 MCP 服务只暴露其部分工具（工具白名单），以便控制上下文预算与能力面。
15. 作为内部用户，我想在启动时若某服务连接失败或宿主缺少运行器（npx/uvx/docker/dnx）就看到中文错误说明（与技能的加载错误同处展示），以便快速区分是配置问题还是环境问题。
16. 作为内部用户，我想让连接失败的服务在修复后经启用/重载触发重连，以便不必重启主服务。
17. 作为内部用户，我想在确认卡与列表上看到「官方源 · 发布者已验证」徽标及提示「仅表示发布者身份经 Registry 验证，不代表代码经过安全审计」，以便正确理解信任边界。
18. 作为内部用户，我想让 deprecated 的条目灰显并展示原因、deleted 的条目不上架，以便目录内容与 Registry 状态一致。
19. 作为部署管理员，我想让所有密钥统一走 `.env` + `${VAR}` 占位（含启动时未解析占位符即报错并禁用该服务），以便配置文件永远不含明文密钥。
20. 作为部署管理员，我想让在线目录的外网元数据交互继续集中在爬取服务隔离区、主服务经 `/market/*` 代理消费，以便维持「独立部署 = 包原样搬出」的可分离架构。
21. 作为部署管理员，我想从本地 `server.json` / `mcp.json` 文件批量导入连接定义，以便复用生态既有配置资产。
22. 作为维护者，我想让 MCP 工具经唯一适配器灌入同一个工具注册表（引擎零改动），以便 ReAct 状态机（ADR-0001）与终止规则（ADR-0002）完全不动。
23. 作为维护者，我想让与内置工具命名冲突、或清洗后超长/重名的 MCP 工具被拒绝加载并报错（fail loud），以便行为可预期、不静默改名。
24. 作为维护者，我想让爬取服务 schema 泛化为「通用 manifest + 资产类型 kind」，以便后续新资产类型（ClawHub 等）不再复制双轨 schema。
25. 作为维护者，我想让工具总数上限可配、超限在装配期报错并提示禁用部分服务，以便上下文预算有硬闸门。
26. 作为内部用户，我想让 MCP 服务不参与 `/技能名` 前缀路由（它没有技能正文），以便该路由契约保持语义纯粹。

## 实现决策（Implementation Decisions）

**范围与交付切分**：管理面 + 运行时接入一起交付（「装了即用」不允许半成品），分提交落地，按序：① 连接定义模型与管理面 API → ② 爬取服务 Registry 适配器与 schema 泛化 → ③ 运行时接入（client/生命周期/命名/闸门泛化）→ ④ 观察值视图 + 旁存续读 → ⑤ WebUI 市场视图泛化 → ⑥ 配置与文档同步。

**资产与存储**：
- 可安装资产 = MCP 服务的**连接定义**（不是包本身）：npm/pypi/nuget/cargo/oci 坐标合成运行器命令模板，包由运行器运行时拉取；本期不落盘任何可执行物。
- 单一声明式连接定义文件为唯一事实源（对位技能包的文件态约定），条目决策形状：

```json
{
  "name": "io.github.acme/filesystem",
  "transport": "stdio",
  "command": ["npx", "-y", "@acme/mcp-fs@1.2.3"],
  "url": "https://mcp.acme.dev/mcp",
  "env": { "ACME_TOKEN": "${MCP_ACME_TOKEN}" },
  "enabled": true,
  "source": "catalog:mcp-registry | local | import:<path>",
  "max_observation_chars": 4000,
  "enabled_tools": ["read_file"]
}
```

  stdio 用 `command`（argv 列表），远程用 `url`（支持 `${VAR}` 变量替换）；`max_observation_chars`/`enabled_tools` 可选。
- 安装来源：在线目录（官方 MCP Registry）、手写编辑、本地导入（`server.json` / `mcp.json`）。**不做 git 安装器**（MCP 无 git 仓库包形态标准，发现需求由 Registry 覆盖）。
- 重载语义对位技能：装配时全量加载 + 写操作即时同步内存与文件态；外部手改经重载端点/重启生效。

**transport 与进程边界**：支持 stdio 与 streamable-http；**不做 sse**（协议已废弃）。stdio 以 argv 列表直起子进程、不经 shell —— 这是硬约束，源于 Registry schema 对参数拼命令行的命令注入警告；确认卡必须展示拼装后的完整命令原文并附「确认 = 授权本机执行该命令」提示行。

**运行时**：采用官方 `mcp` Python SDK，仅主服务依赖引入；爬取服务不引入（它只拉元数据、不讲 MCP 协议），依赖污染边界不变。

**连接生命周期**：启动时对全部启用服务建连并经 `tools/list` 拉取工具表灌入注册表；连接失败或宿主缺运行器（`shutil.which` 检测 npx/uvx/docker/dnx）→ 中文错误进加载错误列表（对位技能 load_errors）并标记该服务连接失败；启用/重载触发重连；调用中连接断开自动重连一次并重试该次调用；stdio 子进程随主服务存续、退出统一回收（atexit）。不做「懒连接」：function calling 的工具 schema 必须来自 `tools/list`，懒最多懒到装配期，无意义。

**工具命名与暴露**：
- 命名 `mcp__<服务短名>__<工具名>`；Registry 的 reverse-DNS 全名清洗入名（`/`、`.` → `-`），遵守 function name 字符集与长度约束；清洗后重名或超限 → 拒绝加载该服务并报错（fail loud）；展示层保留全名。
- 聊天通道的工具闸门泛化：启用服务的 `mcp__*` 工具与既有元工具并列进入可调用集；任务通道全量暴露；禁用即从注册表摘除该服务全部工具。MCP 工具对模型就是普通工具（观察值默认截断），符合「新增工具只改注册表，引擎不感知」。
- MCP 服务不参与 `/技能名` 前缀路由，无激活类元工具（全量暴露后无激活概念）。

**上下文预算闸门**：条目级 `enabled_tools` 白名单过滤 + 可配的工具总数上限；超限在装配期 fail loud 报错、提示禁用部分服务。不引入「动态清单 + 元工具按需解锁」模式（留作将来工具爆炸的退路，改动点已知：聊天闸门 + 动态清单均现成）。

**观察值视图与旁存续读**（兼顾完整返回与防上下文打爆）：
- 视图大小全局可配（默认 4000），条目级 `max_observation_chars` 覆盖，0 = 全量直灌不旁存。
- 凡被截断的观察值必旁存：完整结果进内存句柄池（LRU + 总字节上限，超限淘汰最旧），视图尾注标注「全文共 N 字符」与续读指引。
- 新增内置元工具 `read_tool_result(handle, offset)`（进入聊天闸门允许集），返回分段内容；句柄失效返回报错观察值。不落盘旁存（现状「重启后历史与轨迹清空」，无跨重启需求）。
- 与既有机制的关系：技能元工具 `use_skill` 的 full_result（技能正文是刻意加载的上下文）不动；上下文上界 = 视图大小 × 迭代上限，续读调用计入迭代预算，与 ADR-0002 双层终止一致（不新增终止层）。

**密钥与配置**：确认卡按 Registry 的结构化声明（环境变量/请求头的 name/isRequired/isSecret/default/choices/format）收集必填项，值写入 `.env`，连接定义只留 `${VAR}` 占位；启动时未解析的占位符 → 报错并禁用该服务。展示侧 endpoint 与 env 值脱敏。新配置项（连接定义位置、视图大小、工具总数上限等）同步 `.env.example` 与 README。

**信任模型**：一律单次确认卡（唯一人闸，与技能市场同构，不做多步审批）；本期不做免确认白名单、不做审计链路。徽标体系：Registry namespace 验证类型（GitHub/DNS/HTTP）→「官方源 · 发布者已验证」，title 提示「仅表示发布者身份经 Registry 验证，不代表代码经过安全审计」；`status=deprecated` 灰显 + 原因（statusMessage），`deleted` 不上架；既有审计徽标（AuditBadge）对 MCP 条目统一 unknown。

**在线目录（爬取服务隔离区）**：
- 新增官方 MCP Registry 适配器（唯一本期在线源）：匿名只读 API（`/v0.1/servers` 系列）、游标分页、search 仅名称子串、增量同步用 `updated_since` 水位（存入源状态）、详情路径参数 URL 编码、低频刷新（对齐官方聚合器预期，沿用现有刷新间隔配置）。Registry 处于 preview，适配器是唯一接触点，fixture 测试便于 schema 演进跟进。
- schema 泛化：条目缓存加 `kind` 列（skill / mcp）；目录包与详情的技能专用字段（`skill_md`、SKILL.md 专用解析）改通用 manifest（manifest 路径 + 文本），改名直接替换、README 的 `/internal/*` 合同同步更新（两服务同仓同版本，无外部消费者）；清洗（去控制字符/压空白/截断）与「清洗不拒绝」的信任边界策略照旧。
- 本期目录安装只装连接定义；`mcpb` 单文件包条目展示但标「暂不支持安装」（留安装坐标扩展点，后续需下载 + sha256 校验）。

**网络边界（决策变更）**：撤销「主服务默认零外网」——远程 MCP 端点连接是主服务直连的交互路径，经隔离区中转不现实。约束降级为**模块/服务代码分离**：外网元数据交互集中在爬取服务隔离区，MCP 会话流量走主服务；README/AGENTS.md/CONTEXT.md 的零外网表述按此改写（见「备注」）。

**管理面 API**：对位技能管理面新增 `/mcp*` 一套（列表/详情/启用/禁用/删除/安装/重载），请求响应沿用逐条 installed/skipped/invalid 报告 + warnings 形态；写操作纳入既有全局聊天锁串行化；只读端点不取锁。

**WebUI**：市场视图泛化为统一市场——在线浏览与已安装双面板加资产类型切换（技能 / MCP）或混排 + 类型徽章；确认卡泛化（manifest 预览 + 密钥表单 + 命令原文 + 风险提示行）；安装报告与启停删卡复用；`/` 弹层不混入 MCP；渲染继续坚持纯文本（防注入约定）。

## 测试决策（Testing Decisions）

**好测试的定义**：只测外部行为——HTTP 响应、SSE 帧序列、工具注册表内容（名字/schema 集合）、文件系统状态（连接定义/`.env` 落盘内容）、子进程命令行形态——不测内部调用次数与私有方法。

**测试缝方案（已经用户确认）**：
- **唯一新缝 = MCP client factory 注入**：连接管理器构造参数接受 client factory（默认 = 官方 SDK client），在装配层收口；测试注入脚本化 fake client（`tools/list` 返回预设工具表；`tools/call` 按脚本返回正常结果/抛错/超大结果/中断连）。哲学对位爬取服务适配器的 cloner 注入缝。
- 其余全复用既有缝，零新增：装配函数整体换装（管理面 API 测试）、目录 client fake 注入（代理与安装、断言主服务安装路径无意外外网）、脚本化 LLM fake（闸门泛化、`mcp__*` schema 出现、截断视图与续读经工具轮断言）、StubSettings + 临时目录（配置与占位符解析）、适配器 fixture 驱动 + FakeHttpClient（Registry JSON fixture，测试不发真实请求）。
- **真协议锚点**（不是缝）：tests fixture 放最小 Python MCP server（FastMCP，当前解释器直起），真 stdio client 跑通 initialize → tools/list → tools/call，仅一个用例，锚「官方 SDK 用法没接错」。

**覆盖模块**：连接定义解析/校验（含占位符解析失败禁用）、管理面 API 全套、Registry 适配器（fixture 驱动：分页/增量/状态过滤/URL 编码）、schema 泛化回归（技能侧不回归）、运行时接入（命名冲突 fail loud、runner 缺失检测、连接失败进加载错误、断连重连一次）、观察值视图与旁存续读（超大结果脚本：视图尾注、分段续读、句柄失效、字节上限淘汰）。

**Prior art**（既有同类测试）：技能资产模型/校验/安装器测试（test_skills.py）、管理面 API 测试（test_skills_api.py）、目录代理与安装测试（test_market_api.py，含零意外外网断言与 urllib 回归锚）、SSE/闸门/路由测试（test_server_stream.py）、适配器 fixture 测试（test_catalog_sources.py + tests/fixtures）、脚本化 fake 基建（tests/fakes.py）。git 离线克隆手法本期不需要（不做 git 安装器）。

## 非目标（Out of Scope）

- sse transport（协议已废弃）
- `mcpb` 单文件包的下载安装（sha256 校验 + 落盘，留扩展点）
- git 安装器
- 已验证源免确认白名单 / 任何形式的自动放行
- 第三方安全审计链路（AuditBadge 对 MCP 恒为 unknown）
- 「动态清单 + 元工具按需解锁」的工具暴露模式（留作工具爆炸退路）
- 第二家在线源适配器（Smithery / ClawHub / mcp.so）
- MCP 协议的 prompts / resources / sampling / elicitation；动态 OAuth 授权流（仅静态 env/header 密钥）
- `/` 弹层与 `/技能名` 路由纳入 MCP
- 多会话持久化（重启清空现状不变，旁存句柄池同样不持久）
- stdio 沙箱（不做；风险经确认卡与文档披露）
- CLI 侧改动（CLI 工具调用随注册表自然生效，无 CLI 专属功能）
