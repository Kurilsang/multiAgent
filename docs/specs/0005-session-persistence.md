# SPEC-0005：多会话持久化与断连续流（会话落库 + 任务轨迹重放 + 任务生命周期解耦）

状态：已定稿（grilling 会话逐条确认 + to-spec/to-tickets 落票）· 日期：2026-10-10
关联：[SPEC-0004](0004-multi-agent.md)（本 spec 解禁其非目标「多会话持久化与任务恢复」）、[SPEC-0003](0003-mcp-market.md)、[ADR-0001](../adr/0001-state-machine-for-react-loop.md)、[ADR-0002](../adr/0002-dual-layer-termination.md)、[ADR-0003](../adr/0003-multi-agent-orchestration.md)、CONTEXT.md「任务」「轨迹」「主对话」「审计日志」「叫停」「旁存续读」。

## 问题（Problem Statement）

当前服务是**单会话内存上下文**：整个进程只有一个主对话对象，没有任何会话标识（请求体只有消息文本与可选厂商），重启即清空；任务轨迹只在审计日志里留痕，只可回看不可恢复；WebUI 的聊天历史**只存在于 DOM**（没有消息数组、没有任何客户端持久化），刷新页面等于丢失全部历史。

更严重的是，文档承诺的「SSE 断连即取消叫停」**实测不成立**。断连时服务端既不叫停也不清理：同步生成器被 Starlette 的线程池驱动（shielded CancelScope）直接遗弃，收尾分支不执行，于是**会话锁被永久持有**——`/export` 随之超时，`/agent/stop` 报告成功但实际无效（取消标志只在迭代边界轮询，引擎正卡在厂商调用里），任务在后台无声跑完，审计日志停在断连那一刻。用户看到的是「刷新页面 = 任务卡死 + 服务逐渐不可用」。

用户视角的短板按优先级：**① 断连即失控（真实故障）→ ② 重启后历史与轨迹清空 → ③ 无法并行开展多段对话**。审计日志已在手（逐事件 JSONL），是这次持久化的自然底座。

## 方案（Solution）

**会话成为一等概念并落库**：`data/sessions.db`（SQLite，WAL）持久化会话与消息；请求可带会话标识，不带则落到默认会话；WebUI 打开时按 URL 中的会话标识加载，没有则空页面，用户首条消息即时建会话并改写 URL；会话侧栏支持新建/切换/重命名/删除。用户消息**在调用模型之前**落库，失败留痕不回滚，思考链一并持久化；页面加载时把历史重放进 DOM，刷新后与实时页面一致。展示全量，入模仍按上下文上限截断。

**任务生命周期与 HTTP 连接解耦**：任务在后台线程执行，事件带单调序号进内存缓冲并同时落审计 JSONL；SSE 端点只做订阅，断连 = 退订（**不置取消、不泄漏锁**）；`/agent/stop` 按任务标识定位并在厂商流内即时生效。任务运行期间管理面（技能/MCP/导出）不再被阻塞。客户端可凭任务标识与已收序号**重连续流**：先补发缺口事件，再转实时。

**轨迹回放复用审计日志**：JSONL 是任务事件的唯一权威副本，SQLite 只存任务索引（归属、状态、起止）；刷新后把事件重放进现有时间线渲染器。没有终态事件的任务判定为**已中断**，如实标注并提供「重跑」（新任务，非续跑）。

**明确不做「进程重启后续跑同一任务」**：那需要工具副作用幂等性与不可恢复资源（MCP 会话、厂商流、线程池、旁存句柄池）的重建语义，代价与风险都不成比例。本 spec 交付的是「重启后一切都在、可回看、可重跑」与「断连后任务照跑、可接回」，**不是**「死后复生」。

## 用户故事（User Stories）

1. 作为内部用户，我想让主对话与任务轨迹在服务重启后依然存在，以便关掉终端或重启服务不会丢掉工作成果。
2. 作为内部用户，我想在浏览器刷新后看到与刷新前完全一致的历史（含思考链、工具步骤与错误提示），以便刷新不再等于从头开始。
3. 作为内部用户，我想在任务跑到一半时关掉标签页或断网，任务**继续在后台跑完**，以便长任务不被一次误操作毁掉。
4. 作为内部用户，我想在重新打开页面后接回正在跑的任务并看到它继续实时输出，以便断连后不必重跑。
5. 作为内部用户，我想让断连**不再**导致任务被取消、锁被占用、服务逐渐卡死，以便一次断连不会污染整个服务。
6. 作为内部用户，我想让「停止」按钮在任务卡在厂商调用时也能真正生效，以便成本可控。
7. 作为内部用户，我想同时开展多段互不干扰的对话（例如一段写代码、一段查资料），以便不同工作不互相污染上下文。
8. 作为内部用户，我想看到会话列表并一键切换、重命名、删除，以便管理累积的会话。
9. 作为内部用户，我想让「清空」变成「新建一段对话」而不是销毁现有记录，以便误点不会造成不可逆损失。
10. 作为内部用户，我想让会话名默认取首条消息，以便不必手动命名就能认出每个会话。
11. 作为内部用户，我想在任务运行期间照常安装/启停技能、重载 MCP、导出对话，以便管理操作不被别人的长任务阻塞。
12. 作为内部用户，我想在同一会话已有任务在跑时被**明确告知**而不是静默排队，以便知道该等还是该停。
13. 作为内部用户，我想在不同会话里同时跑任务而互不阻塞，以便并行推进多条工作线。
14. 作为内部用户，我想让每条回答都标明是哪个厂商/模型答的，并且导出时归属正确，以便在切换厂商后仍能追溯。
15. 作为内部用户，我想让请求失败的那一轮留下痕迹而不是被悄悄抹掉，以便知道「我刚才问过、它失败了」。
16. 作为内部用户，我想在刷新后看到被中断的任务标注「已中断」并保留已有进展，以便知道它死在哪一步而不是假装无事发生。
17. 作为内部用户，我想对中断的任务点「重跑」并清楚知道这是一次新任务（不是续跑），以便语义不含糊。
18. 作为内部用户，我想让长会话在页面上完整展示但只把最近若干条发给模型，以便既看得全又不烧 token。
19. 作为内部用户，我想让聊天通道里的工具步骤（思考/行动/观察）也随历史持久化，以便刷新后与实时页面完全一致。
20. 作为内部用户，我想让旧的不带会话标识的接口调用继续可用（落到默认会话），以便既有脚本与文档不失效。
21. 作为部署管理员，我想通过环境变量指定会话库位置，以便把数据放到我想要的位置。
22. 作为部署管理员，我想在会话库版本高于当前代码时**明确报错**而不是静默损坏数据，以便升级/回滚安全。
23. 作为部署管理员，我想在误启第二个进程共享同一数据目录时被明确拒绝，以便不会静默写坏数据库。
24. 作为部署管理员，我想让会话库与审计日志分开存放，以便清理日志时不会误删会话。
25. 作为部署管理员，我想让审计日志在删除会话后依然保留，以便排障资产不随会话消失。
26. 作为维护者，我想让会话历史与任务轨迹各有单一权威副本（前者在库、后者在 JSONL），以便不出现「两份不一致信谁」的问题。
27. 作为维护者，我想让轨迹回放复用现有时间线渲染器，以便不新增第二套渲染逻辑。
28. 作为维护者，我想让任务事件带单调序号与时间戳，以便重连补发、去重与排序都有据可依。
29. 作为维护者，我想让任务生命周期不再绑定 HTTP 连接（连接只是订阅者），以便这是架构上的修正而不是补丁。
30. 作为维护者，我想让被推翻的旧设计决策（「断连即取消」「不提供恢复」）在新 ADR 里留档，以便后人知道为什么改。
31. 作为维护者，我想让 CLI 维持进程内单会话语义不变，以便这个入口的行为可预测。
32. 作为维护者，我想让新增的磁盘写入沿用既有的临时目录注入缝，以便测试套件保持封闭、不污染真实数据。

## 实现决策（Implementation Decisions）

### 范围与交付切分

分提交按序落地，对应票据 T1–T6：

1. **T1 任务生命周期与 HTTP 连接解耦**（prefactor，修断连泄漏）
2. **T2 会话持久化闭环（单会话）**
3. **T3 多会话管理**
4. **T4 任务归属与轨迹回放**
5. **T5 断连续流**
6. **T6 文档与配置收口**

T1 与 T2 无依赖可并行；T4 依赖 T1（序号）与 T3（会话归属）；T5 依赖 T1（缓冲）与 T4（任务索引）；T6 收口。

### T1：任务生命周期与 HTTP 连接解耦

**这是对既有实现缺陷的修正，不是纯重构。** 现状：任务在 SSE 生成器内同步执行，整个生成器体持会话锁；断连时生成器被线程池遗弃、收尾分支不执行，锁永久泄漏。

- **任务改为后台执行体**：任务在独立线程中运行，产出的引擎事件写入**每任务事件缓冲**（内存列表，带单调 `seq`）并同时追加审计 JSONL。事件缓冲是「可重放的历史」，JSONL 是「崩溃一致的权威副本」。
- **SSE 端点退化为订阅者**：只从缓冲读取并转发，不持有任务、不持锁。断连 = 退订；**退订不置取消标志**（这是本 spec 的核心行为改变）。
- **锁拓扑改为「每会话一把锁 + 管理面独立锁」**：管理写操作（技能安装/启停/删除、MCP 启停/重载/重授权/安装）改用管理锁，**不再被在跑任务阻塞**；读接口（技能/MCP/厂商/市场）继续无锁。会话锁只保证「同一会话的历史写入不交错」。
- **同会话并发语义**：同一会话同时最多一个在跑任务；期间对该会话再发起任务或聊天一律**明确拒绝**（中文提示已有任务在跑，请等待或先停止），**不排队、不阻塞**。
- **`/agent/stop` 按任务标识定位**，且取消必须能在**厂商流内部**被观察到（当前只在迭代边界轮询，卡在厂商调用时停止按钮无效）。取消后以 `partial` 收尾并附已完成进展。
- **优雅停机**：注册关闭钩子，尽量置取消并等待任务收尾（当前连按两次 Ctrl+C 仍会被非守护工作线程阻塞，属已知事实，本 spec 至少保证置取消与状态落盘）。

### T2：会话持久化闭环

**存储底座**：SQLite（stdlib `sqlite3`，无新增依赖），位置 `data/sessions.db`，新增配置项 `SESSION_DB`（相对项目根路径，`str` 类型，沿用既有路径类配置惯例），`.gitignore` 增加 `data/`，同步 `.env.example` 与 README。

**与审计日志分开存放**：会话库是**一等状态**，审计日志是可丢弃的留痕；清理日志不应误删会话。

**连接模型**：单连接 + 线程锁 + 允许跨线程使用，沿用既有 SQLite 先例的连接形状，但**升级三处**：① 启用 WAL（后台任务线程写事件与 HTTP 线程读历史是真实并发）；② 用 `PRAGMA user_version` 做 schema 版本 + 有序迁移，**库版本高于代码版本时 fail loud**（既有先例吞掉 `OperationalError`，那适合加列、不适合改结构）；③ 启动时写入**运行时心跳行**（pid + 时间戳），发现心跳新鲜且 pid 不同则拒绝启动并打印中文原因（纯 stdlib、跨平台；替代文件锁）。

**数据形状**（决策密集，原型级）：

```
sessions(id TEXT PK, name TEXT, created_at TEXT, updated_at TEXT)
messages(id INTEGER PK AUTOINCREMENT, session_id TEXT, seq INTEGER,
         role TEXT, content TEXT,
         provider TEXT NULL, model TEXT NULL,
         status TEXT, reasoning TEXT NULL, created_at TEXT)
tasks(task_id TEXT PK, session_id TEXT, task TEXT, status TEXT,
      started_at TEXT, finished_at TEXT NULL, log_path TEXT)
runtime(pid INTEGER, heartbeat_at TEXT)
```

`messages.status` 表达该轮的终态（正常 / 失败 / 部分完成），`reasoning` 存思考链，`provider`/`model` 记录该条回答的实际来源。

**写入时机**：用户消息**在调用模型之前**落库；回答完成后追加 assistant 消息。**失败不回滚、留痕并标记该轮失败**——既有「请求失败时撤回用户消息」的语义作废，因为「看得见失败发生过」比「页面干净」更有价值。

**持久化粒度**：思考链与错误提示一并持久化；**聊天通道的工具轮次（思考/行动/观察）同样持久化**，否则刷新后的页面会比实时页面少一截，违背「刷新后一致」的初衷。

**厂商归属**：每条 assistant 消息持久化 `provider` + `model`（取请求解析后的实际目标，不是当时的默认值），WebUI 元信息与导出据此显示。这同时修掉既有缺陷：导出把当前默认厂商套用到全部历史消息。

**展示与入模分离**：页面展示全量历史，发给模型仍按上下文上限截断。基于持久化历史的摘要压缩**不在本 spec**。

**恢复回路**：新增「读取某会话消息」的查询接口；WebUI 页面加载时拉取并**重放进 DOM**（不引入前端消息数据模型，导出按钮的 DOM 遍历逻辑不变）。

### T3：多会话管理

- **会话标识**：与任务标识同风格的短十六进制随机串（沿用既有先例，人眼可读、URL 安全）。
- **不带标识的请求落到持久化的默认会话**，既有接口调用方式不破（不做 API 版本化）。
- **WebUI 路由**：URL 带会话标识则进入该会话；不带则**空页面**。用户发送首条消息时**即时新建会话**并把 URL 改写为该会话标识。
- **会话名**：默认取首条用户消息截断，支持手动重命名。
- **「清空」改为「新建会话」**：当前会话保留在列表中，页面切换到一段全新记录（不再销毁任何东西）。
- **会话 CRUD**：新建、列表、重命名、删除；删除为**硬删**（单用户，软删只增状态）。
- **WebUI 会话侧栏**：列表 + 切换 + 新建 + 重命名 + 删除，显示任务状态指示。

### T4：任务归属与轨迹回放

- **审计头增加会话归属**；**任务事件增加单调 `seq` 与时间戳**（当前事件无序号无时间戳，顺序仅靠文件行序）。
- **子 agent 标识改为跨进程稳定**：现标识内嵌 CPython 对象 id，跨进程不可读，需改为稳定编号。
- **SQLite 任务索引**：记录任务标识、所属会话、任务文本、状态、起止时间、日志路径——**只存索引，不复制事件**（避免两份不一致）。
- **刷新后回放**：按会话拉取任务索引与事件，**重放进现有时间线渲染器**（复用，不新增渲染器）。
- **中断判定与呈现**：审计日志无终态事件 = 已中断；UI 标注「已中断（进程重启）」并展示已有部分进展；提供「重跑」按钮（以同一任务文本发起**全新任务**，文案明示非续跑）。
- **孤儿日志**：无会话归属的旧日志不进任何会话时间线，仅供人工排障，不做迁移猜测。

### T5：断连续流

- **端点复用**：`/agent/stream` 接受任务标识与已收序号；服务端**先补发缺口事件再转实时**，客户端无需判断该连哪个端点。
- **缓冲策略**：内存事件缓冲优先（快），进程重启后从 JSONL 补历史并**明确标注任务已中断**（不假装还活着）。
- **多订阅者广播**：同一任务的事件广播给所有订阅者（无鉴权的单用户场景，多标签看到同一任务进展是合理预期）。
- **任务状态查询**：提供查询某任务当前状态与已产生事件数的接口，供 UI 决定是否重连。

### T6：文档与配置收口

- 新增配置项同步 `.env.example` 与 README（项目约定）。
- **新立 ADR-0004**：记录「任务生命周期不再绑定 HTTP 连接」——这是对既有「断连即取消叫停」决策的**修正**，必须留档（对位 ADR-0003 在 SPEC-0004 收口票落地的惯例）。
- **SPEC-0003/0004 的非目标处加指针**指向本 spec，不重写历史。
- **CONTEXT.md 新增术语**：会话（Session）、断连续流（Reattach）。既有「审计日志」词条中「不提供恢复」的表述需按本 spec 修正为「只可回看，可重放渲染，不提供续跑」。
- **已知限制更新**：README/AGENTS.md 中「重启后历史与轨迹清空」「SSE 断连任务不恢复」两条改写为现状；补一条「CLI 仍为进程内单会话，不读写 WebUI 的会话库」。
- 顺手关闭 SPEC-0004 的 spec 票（其实现票已全部落地）——文档卫生，不计入本 spec 实现范围。

### 明确不做：进程重启后续跑同一任务

- 进程死亡时正在执行的工具调用可能**已产生副作用**（写文件、外部请求、MCP 调用），「续跑」要么至少一次重放（可能重复副作用）、要么跳过（可能丢结果），两者都需要工具级幂等性契约——当前不存在。
- 不可恢复资源：MCP 会话（独立事件循环线程 + 子进程）、在飞厂商流、线程池 future、子 agent 引擎实例、旁存句柄池（明确不落盘）、取消令牌。
- **旁存续读的跨重启后果如实呈现**：轨迹里形如「续读某句柄」的工具调用在重启后无法满足，UI 与错误信息如实说明，不伪造。
- 引擎可恢复状态（轨迹消息列表、迭代计数、派发预算）目前全在生成器帧局部变量里，从不落盘；把它变成可续跑需要一次引擎级改造，留待有了真实重启数据后再评估。

## 测试决策（Testing Decisions）

**好测试的定义**：只测外部行为——HTTP 响应与状态码、SSE 帧序列（含 `seq` 单调性与补发缺口）、数据库里的行、审计 JSONL 内容、页面重放后的 DOM 结构、拒绝语义——不测内部调用次数与私有方法。

**测试缝**：**不新增缝**，沿用既有两条——① 构造参数注入临时路径（会话库路径、审计目录、技能目录、token 文件）；② 装配根替换（既有 `_build_wiring(tmp_root)` 形状）用于整机测试。会话库用**真实临时 SQLite**，不用 fake 存储（照既有 SQLite 测试先例）。

**覆盖模块**：

- **连接解耦**：断连后任务继续跑完（审计日志持续增长）、会话锁被释放（后续请求不被阻塞）、管理操作在任务期间可用、退订**不**置取消。
- **停止语义**：任务卡在厂商流时停止仍然生效并以 `partial` 收尾。
- **持久化**：用户消息先落库（模型调用前）、失败留痕不回滚、思考链与工具轮次落库、厂商归属正确、展示全量与入模截断分离。
- **多会话**：会话 CRUD、默认会话兜底、首条消息建会话、`/reset` 行为变更、重命名、硬删。
- **轨迹回放**：事件 `seq` 单调、会话归属、中断判定（无终态事件）、重跑生成新任务标识、孤儿日志不入时间线。
- **续流**：按序号补发缺口、多订阅者广播、进程重启后补历史并标注中断。
- **存储健壮性**：库版本高于代码时 fail loud、迁移有序执行、多进程心跳检测拒绝启动、WAL 生效。
- **隔离**：新增数据目录确实被 gitignore（照既有「断言路径被忽略」的测试形状）。

**Prior art**：既有 SSE 流式接口测试的帧断言模式、既有 SQLite 测试的临时库与旧库迁移模式、既有注入缝哲学（网络与交互全走注入）、既有「断言路径被 gitignore」测试。

## 非目标（Out of Scope）

- **进程重启后续跑同一任务**（详见实现决策末节；重启后一切可见、可回看、可重跑，但不续跑）
- 工具调用副作用幂等性契约、工具级重放/补偿
- 旁存句柄池持久化（继续不落盘）
- 基于持久化历史的自动摘要压缩与长期记忆
- CLI 多会话（CLI 维持进程内单会话，不读写会话库）
- 鉴权、多用户、跨设备同步（网关逻辑另议）
- 多进程部署与跨进程任务归属/事件广播（单进程边界，检测到共享数据目录即拒绝启动）
- 会话保留策略与自动清理（保留策略记为后续扩展点）
- 会话导入/导出为可移植格式、会话分享
- 审计日志格式的历史数据迁移（旧日志不做归属猜测）
- 自动任务路由、角色配置文件（SPEC-0004 非目标不变）

## 备注（Further Notes）

- **术语缺口（留给 /domain-modeling 补录 CONTEXT.md）**：会话（Session）、断连续流（Reattach）；既有「审计日志」词条需按本 spec 修正「不提供恢复」的表述。
- **被推翻的旧决策**：SPEC-0003/0004 把「多会话持久化与任务恢复」列为非目标、SPEC-0004 明确「SSE 断连即取消叫停」——本 spec 主动解禁并修正，ADR-0004 留档。这是项目变大后的自觉取舍，不是漏做。
- **实测发现（本次 grilling 的副产品）**：断连收尾分支从未执行、会话锁泄漏、`/agent/stop` 在厂商调用期间无效、优雅停机被非守护工作线程阻塞。这些是**既有缺陷**而非新需求，T1 一并修正。
- **成本与风险**：会话库会随思考链显著增长（思考链是大头）；全量展示 + 截断入模的差异需在 README 写明，否则会被误认为上下文丢失。
- **架构意义**：T1 之后「任务」不再从属于一次 HTTP 请求，而是有自己的生命周期与标识——这是后续网关逻辑（路由/鉴权/审计）与定时编排的前置条件。
- **UI 不变式**：WebUI 继续以 DOM 为唯一渲染目标，刷新恢复靠重放；这保证了导出按钮（DOM 遍历）与既有渲染路径零改动。
