# SPEC-0006：会话内记忆与上下文预算（预算分层装配 + 滚动摘要 + 观察值降级）

状态：已定稿（grilling 逐条确认 + to-spec 落票）· 日期：2026-10-12
关联：[SPEC-0005](0005-session-persistence.md)（本 spec 解禁其非目标「基于持久化历史的自动摘要压缩与长期记忆」中的**会话内部分**；「长期记忆」仍留白）、[SPEC-0004](0004-multi-agent.md)、[ADR-0002](../adr/0002-dual-layer-termination.md)、[ADR-0003](../adr/0003-multi-agent-orchestration.md)、CONTEXT.md「主对话」「会话」「观察值视图」「旁存续读」「思考链」（新增术语：「上下文预算」「记忆块」「滚动摘要」，见实现决策）。

## 问题（Problem Statement）

长会话聊到一半，助手会忽然"失忆"：它忘了第 3 轮定下的约束、推翻自己早前的结论、要求用户重新交代背景。用户粘贴一段长文档、或模型连续调用几个返回大块结果的工具后，症状会急剧恶化——真正重要的对话早被挤出了模型能看到的范围。

根因是入模截断只有一条规则：**按条数取最近 N 条**（`MAX_CONTEXT_MESSAGES`，默认 20），system 之外一律"旧的不要"。截断决策不知道自己在省什么：20 条短消息可能只有 3k token，20 条带大观察值的消息可能超过 100k token，系统对此毫无感知；一条工具观察值的视图就占 4000 字符，几条就能吃掉大部分真实窗口。与此同时，**全量历史一直完整保存在会话库里**——页面展示全量、可导出、可检索，唯独发给模型的那部分用最粗暴的方式裁剪。所谓失忆不是数据丢了，是**该喂进去的没喂进去**。

用户视角的短板按优先级：**① 长对话失忆（约束丢失、自相矛盾）→ ② 工具观察值挤爆窗口**。前者是体验崩坏，后者是它的主要加速器。

## 方案（Solution）

**把"取最近 N 条"换成"按预算分层装配"**。装配器每次入模前估算候选消息的 token 占用（零依赖纯函数估算，无需 tokenizer），在 `上下文预算`（context window 减输出预留）内按优先级从高到低装填：**system 与技能清单 → 记忆块（滚动摘要）→ 最近 N 轮对话 → 本轮工具观察值视图 → 更早对话**。装不下的更早对话不直接丢弃，而是**吸收进滚动摘要**（每会话一条、随吸收进度合并更新、带覆盖水位），摘要作为记忆块在下一轮入模，位置固定在 system 之后、历史之前。全量历史仍留会话库，展示与导出不受影响，被摘要吸收的原话随时可回查。

**观察值降级共享化**：观察值视图不再是固定 4000 字符，而是预算驱动——预算紧张时视图按剩余预算压缩（保底下限），全文仍进旁存句柄池，`read_tool_result` 续读照常；`0=全量直灌` 与 `full_result=True`（技能正文、续读结果）语义不变。这一条同时惠及任务通道的 agent 轨迹（共享原语，轨迹历史本身不做摘要）。

**摘要即记忆接口**：装配器只认识"记忆块"这一抽象（一段带来源标注的文本，注入位固定）。本 spec 只实现"会话内滚动摘要"一种来源；**跨会话长期记忆作为第二种来源留接口不实现**——将来接入时无需改动装配器与截断逻辑。

**摘要失败不阻塞**：摘要生成走现有对话通道（当前厂商/模型，一次额外调用，仅在超预算时触发）；失败时降级为现行硬截断行为，如实标注，对话照常进行。

## 用户故事（User Stories）

1. 作为内部用户，我想让长对话进行到 30 轮后助手仍记得第 3 轮定下的约束，以便它不再推翻早前结论、逼我重新交代背景。
2. 作为内部用户，我想让粘贴一段长文档之后的对话仍记得我此前交代的项目背景，以便一次粘贴不会把上下文里的其他东西挤掉。
3. 作为内部用户，我想让工具返回大块结果时不会把真正的对话挤出窗口，以便连续几轮工具调用之后助手还认识我是谁。
4. 作为内部用户，我想让被摘要吸收的原话仍能在页面上看到并可导出，以便需要时能核对"它到底记没记对"。
5. 作为内部用户，我想让摘要标注它覆盖到哪一轮，以便我知道"压缩线"在哪、哪些内容只剩摘要。
6. 作为内部用户，我想让最近几轮对话永远逐字在窗口里，以便追问和改口总是立即生效、不被摘要模糊掉。
7. 作为内部用户，我想让摘要生成失败时对话照常继续（降级为截断），以便一次模型抖动不会让我没法聊天。
8. 作为内部用户，我想让短会话完全感觉不到摘要的存在，以便不为没必要的压缩付代价。
9. 作为内部用户，我想让观察值视图在预算紧张时自动变短但仍可续读全文，以便大工具结果既不挤爆窗口也不丢信息。
10. 作为内部用户，我想让 `read_tool_result` 在视图被压缩后仍然可用，以便需要细节时能取回。
11. 作为内部用户，我想让技能正文、续读结果这类功能性内容不被压缩掉，以便激活的技能和续读流程照常工作。
12. 作为内部用户，我想让任务通道里大工具结果同样不挤爆轨迹窗口，以便长任务不会在中间莫名变傻。
13. 作为内部用户，我想看到每次回答附带的上下文用量信息（估算用量、是否触发了摘要），以便理解它为什么记得/不记得。
14. 作为内部用户，我想让多个会话各自独立维护摘要，以便切换会话不会互相污染记忆。
15. 作为内部用户，我想让服务重启后摘要随会话库一起还在，以便不必每次重启都重新压缩一遍。
16. 作为内部用户，我想让导出包含全部原话（而不只是摘要），以便导出文件是完整档案。
17. 作为内部用户，我想让摘要忠实于原话（约束、结论、待办不丢不造），以便压缩过的记忆仍然可信。
18. 作为内部用户，我想让 CLI 聊天同样享有预算装配，以便两个入口的助手行为一致。
19. 作为部署管理员，我想通过环境变量配置上下文窗口大小与输出预留，以便适配不同厂商/模型的真实窗口。
20. 作为部署管理员，我想让"最近保底条数"继续可配，以便在预算之外保留一条直观的下限保障。
21. 作为部署管理员，我想让摘要的触发与失败在日志里留痕，以便排查"为什么这段被压缩了/没被压缩"。
22. 作为部署管理员，我想让会话库自动迁移到新版本、旧数据不丢，以便升级安全。
23. 作为部署管理员，我想让会话库版本高于当前代码时明确报错，以便回滚不静默损坏数据。
24. 作为维护者，我想让上下文装配只有一个实现点（装配器），以便聊天、任务两条通道与 CLI 复用同一套规则。
25. 作为维护者，我想让 token 估算是一致、保守、可单测的纯函数，以便不引入 tokenizer 依赖也能有稳定的预算依据。
26. 作为维护者，我想让装配规则以"发给模型的消息"为唯一验证面，以便测试断言外部行为而非内部实现。
27. 作为维护者，我想让记忆块成为摘要之外可扩展的注入位，以便将来接长期记忆（L2）时不用推翻装配器。
28. 作为维护者，我想让摘要生成走现有对话通道与既有 LLM 测试缝，以便不新增网络面、测试不发真实请求。
29. 作为维护者，我想让"按条数截断"这个被推翻的旧决策留档 ADR，以便后人知道为什么改。
30. 作为维护者，我想让观察值降级作为共享原语一次实现、两通道受益，以便不出现两套截断逻辑。
31. 作为维护者，我想让本轮彻底不引入新 Python 依赖（无 tokenizer、无向量库、无外部记忆服务），以便保持零密钥、离线可跑的边界。
32. 作为维护者，我想让 README / AGENTS.md / CONTEXT.md / .env.example 在落地时同步更新，以便文档与代码不脱节。

## 实现决策（Implementation Decisions）

### 范围与交付切分

T1 估算器与预算配置 → T2 上下文装配器（分层 + 降级阶梯）→ T3 观察值降级共享原语 → T4 滚动摘要与记忆块（含会话库迁移）→ T5 两通道接入与用量可观测 → T6 文档配置收口（ADR-0005）。分提交，每个提交带对应测试。

### T1：token 估算器与上下文预算

- **估算器为纯函数**（不注入任何依赖）：CJK/全角字形按 1 token/字，非 CJK 按 1 token/3 字符（对主流 BPE 偏保守），每条消息固定加 8 token 结构开销，结果向上取整。目的不是精确，是**一致且保守**——宁可少装不可爆窗。
- **上下文预算** = `CONTEXT_WINDOW_TOKENS`（默认 32000，取三家厂商真实窗口的保守下界）− `CONTEXT_OUTPUT_RESERVE_TOKENS`（默认 4096）。两者进配置并同步 `.env.example`。
- `MAX_CONTEXT_MESSAGES` **语义变更**：从"截断上限"变为"最近轮次保底条数"（默认 20、下限 2 不变）——最近 N 轮永不被摘要吸收、永不因预算被逐出（除非连 system 都装不下，见降级阶梯）。
- 摘要与装配的额外开销计入预算：记忆块按其文本估算占用，参与同一笔账。

### T2：上下文装配器

装配器是**唯一入模实现点**：输入 = system 块 + 记忆块列表 + 全量历史（含观察值），输出 = 发给模型的消息数组 + 装配元数据。聊天通道、任务通道、CLI 全部改走它。

装填顺序（占预算顺序，高→低）：

1. system（协议、技能清单、预激活技能正文）
2. 记忆块（滚动摘要；见 T4）
3. 最近 N 轮对话（`MAX_CONTEXT_MESSAGES` 保底）
4. 本轮工具观察值视图（预算驱动压缩，见 T3）
5. 更早对话（预算有剩余才逐字入模）

**超预算动作阶梯**：

1. 更早对话装不下 → 取"装不下的最旧连续段"**吸收进滚动摘要**（有损但可回查，覆盖水位单调推进），不再逐字入模；
2. 仍超 → 工具观察值视图按剩余预算**等比压缩**至保底下限（`OBSERVATION_MIN_CHARS`，默认 500）；
3. 仍超 → 最近 N 轮中较旧的逐条硬截断（最终保 system + 记忆块 + 最新一条），元数据标注 `degraded`。

装配元数据形状（来自原型推演，编码最终决策）：

```text
context_meta = {
  estimated_tokens: int,      # 入模估算占用
  budget_tokens: int,         # 本次预算
  compressed_upto: int|null,  # 摘要覆盖到的最新消息 seq（null=未触发）
  summary_generated: bool,    # 本次装配是否新生成/合并了摘要
  degraded: bool,             # 是否触发了硬截断兜底
}
```

### T3：观察值降级（共享原语）

- 观察值视图阈值由固定 `observation_max_chars`（默认 4000）扩展为**预算驱动**：装配器给观察值分配剩余预算份额，超出则压缩视图文本；工具级 `max_observation_chars` 覆盖与 `0=全量直灌` 语义不变。
- 视图压缩只影响"进上下文的文本"，全文照旧进旁存句柄池，`read_tool_result` 续读不受影响；视图尾注的续读指引保留。
- `full_result=True`（技能正文、续读结果）**不参与压缩**，按全文估算入账。
- 该原语在任务通道（agent 轨迹）同样生效；**轨迹历史本身不做摘要**（非目标）。

### T4：滚动摘要与记忆块（会话库迁移）

- **每会话单条滚动摘要**：新表 `session_summaries`（会话归属、覆盖水位 `covered_seq`、正文、更新时间），随 `SCHEMA_VERSION` +1 迁移（登记迁移函数，旧库自动升级，高版本 fail loud）。消息本体永不删除——摘要是"入模视图"，不是数据清理。
- **合并式更新**：触发吸收时，摘要生成调用的输入 = 旧摘要正文 + 新吸收段的 user/assistant 原文；输出替换旧摘要，`covered_seq` 单调递增。思考链不入摘要（沿用「不入上下文」约定），工具 steps 不入摘要（属症状 h，另行处理）。
- **摘要生成**走现有对话通道（当前厂商/模型，非流式），仅在超预算触发时发生一次额外 LLM 调用；不为摘要单独配置模型（留扩展点）。
- **失败降级**：生成失败或超时 → 放弃本次吸收、按 T2 阶梯第 3 步硬截断，日志留痕，对话不阻塞。
- **记忆块抽象**：装配器接受"记忆块"列表（来源标注 + 文本 + 覆盖提示），注入位固定。本 spec 仅实现"会话内滚动摘要"来源；**跨会话长期记忆是预留的第二种来源**——不建空表、不实现召回，接口形状在代码中以文档化扩展点形式存在。

### T5：两通道接入与用量可观测

- 聊天通道与 CLI：入模改走装配器；摘要吸收发生在装配期（同步、惰性、落库后不重复触发），不阻塞流式输出。
- 任务通道：agent 轨迹装配复用 T3 观察值降级与预算估算；**不做轨迹历史摘要**，`MAX_TRACE_MESSAGES` 行为保持现状。
- `context_meta` 随响应暴露：HTTP 响应体与 SSE 事件各带一份，WebUI 以时间线角标展示（估算用量 / 摘要水位 / 是否降级），CLI 以小字显示；不新增端点。
- 摘要触发与失败写任务/服务日志留痕。

### T6：文档与配置收口

- ADR-0005「上下文装配采用预算分层，条数截断退居保底」：记录被推翻的旧决策（纯条数截断）与理由。
- CONTEXT.md 新增术语：**上下文预算(Context Budget)**、**记忆块(Memory Block)**、**滚动摘要(Rolling Summary)**；「观察值视图」条目补充预算驱动压缩语义。
- 同步 README（撤下「自动摘要未做」表述）、AGENTS.md（目录约定与下一步指针）、`.env.example`（新配置项）。

### 明确不做：跨会话长期记忆

L2（用户偏好/项目事实跨会话抽取与召回）需要新的记忆归属维度（用户？项目？工作目录？）、写入者与召回策略、以及召回面（关键词/时间衰减/语义检索）的完整设计，与本 spec 的会话内装配是两棵树。本 spec 只保证：将来接入时以第二种记忆块来源进入装配器，**不改动装配、截断与摘要逻辑**。

## 测试决策（Testing Decisions）

- **好测试的定义**：只断言外部行为——发给模型的消息形状、会话库里的内容、用户可见的响应——不断言装配器内部步骤；估算器的单测属于规格级断言（边界值与保守性），不算实现细节测试。
- **主接缝（唯一新增验证面）：入模消息边界**——断言脚本化 LLM fake 实际收到的 messages 数组。复用 `tests/fakes.py` 的 LLM fake 与 `SessionStoreMixin` 临时会话库缝，测试不发真实请求。断言三点：① 入模估算占用不超过预算；② system、记忆块、最近轮次、压缩后观察值按优先级在场；③ 会话库历史仍全量。
- **辅接缝（复用既有）**：Settings 注入（改预算/窗口/保底条数做边界断言）；摘要生成走同一 LLM fake（脚本化摘要回复），不新增网络面。
- **不需要新缝**：估算器是纯函数直接单测；摘要在装配期同步惰性触发，无时钟/后台线程缝。
- **受测模块**：conversation（装配器）、observation（预算驱动降级）、sessions（`session_summaries` 表迁移与滚动更新）、config（新配置项边界）、server 与 cli（两通道接入、context_meta 暴露）、agent（轨迹侧观察值降级生效）。
- **先例**：`test_sessions_api` 的"库全量 vs 入模截断"断言（本 spec 的主缝先例）、`test_conversation` 的截断保 system、`test_observation` 的视图/旁存/0=全量、`test_sessions` 的迁移顺序与高版本 fail loud。
- **验收剧本**（手工/集成各一）：① 30+ 轮长对话后第 3 轮的约束仍被遵守；② 粘贴长文档后前文不丢；③ 连续大观察值后视图压缩但续读可用；④ 摘要失败时降级为硬截断且对话不中断。

## 非目标（Out of Scope）

- **跨会话长期记忆（L2）**：只留记忆块接口，不实现抽取、存储与召回。
- **agent 轨迹历史摘要与 `MAX_TRACE_MESSAGES` 丢中段问题**（症状 b）：轨迹只受益于观察值降级。
- **子 agent 派发上下文传递与 critic 可见范围**（症状 d）。
- **会话通道与任务通道记忆互通**（症状 g）。
- **聊天通道工具轮次落成独立消息行**（症状 h）：摘要只吃 user/assistant 正文。
- **会话保留策略与自动清理**：摘要不是清理，本 spec 不删任何数据。
- 真 tokenizer / token 计费对账、向量库、embedding、外部记忆服务、任何新 Python 依赖。
- 摘要内容审计与质量保证（第三方提示注入面的既有立场不变）。
- 跨用户记忆隔离（当前单用户/低并发定位不变）。

## 备注（Further Notes）

- 摘要生成是一次额外 LLM 调用（仅超预算触发、每会话按吸收进度合并），成本与延迟都发生在装配期；对短会话零影响。
- 估算器偏保守意味着"预算用不完"是常态，这是刻意的：爆窗的代价远高于少装几条。
- 摘要质量依赖当前厂商/模型的指令遵循能力；坏摘要的兜底是"原话全量留在库里、可回查可导出"，而非追求摘要本身完美。
- `MAX_CONTEXT_MESSAGES` 的语义变化（截断上限→保底下限）需在 README 与 `.env.example` 注释中写明，避免既有配置被误读。
- 后续候选：症状 h（工具轮次留痕）改动面小、对失忆有直接缓解；症状 g（双通道记忆互通）需要"任务通道该看到多少会话历史"的契约设计。
